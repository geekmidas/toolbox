:boom: A `RestApi` runs only its own endpoints; a `Worker`'s work and keys stay with the worker

- **A second surface no longer runs every worker or gets their keys.** Any generated server (a `RestApi` whose endpoints a glob finds) was handed every `Worker`'s edges and every queue's and topic's connection string. Its `.gkm/server/crons.ts` and `queues.ts` imported every worker's crons and consumers, and every surface's entry registered the cache and events drivers when anything in the workspace declared a cache or a broker. A surface's process and environment now cover its own endpoints (attributed by the surface each was built from, `api.post` vs `reviewer.post`, not by where the file is). That applies to the compose service's env, the Dokploy application's env, `gkm secrets:add` attribution, the deploy readiness check and the S3 CORS origins. A surface that relied on a worker's keys reaching it, for example a queue's `*_PUBLISHER_CONNECTION_STRING` or `EVENT_PUBLISHER_CONNECTION_STRING` with no endpoint that sends to it, now needs an edge (`.dependsOn([queue])`, `.event(topic, …)`) on the endpoint that uses it.
- **A worker reads its own.** Its env holds its edges, its crons', consumers' and subscribers' edges, the queues its consumers drain and the topics its subscribers are bound to, and the broker its crons schedule through. It no longer gets every carrier in the workspace. `gkm secrets:add` names the worker (`jobs`) as the reader of a credential only its cron uses.
- **`gkm dev` runs a worker's work in one app.** The dev server of the app that hosts the worker runs its crons, consumers and subscribers (the host is the app whose directory holds the work, the same app whose image build writes the worker's entry). Every other dev server runs only its own endpoints. This used to be every app's server, so two surfaces ran each cron twice. That server starts telemetry when its API or a worker it hosts has the edge.
- **`gkm dev --fake` hands a `Credential`'s fake to the containers that read it**, as it does an `ExternalApi`'s: the apps' compose services get `<ID>_CREDENTIALS` from `test/fakes/<id>.ts` when their edges reach the credential.
- **`RedisClientMissing` names only the apps whose process reaches a cache.** An app that reaches none registers no cache driver and needs no `ioredis`.
- **The local stage never touches remote deploy state.** With `state: { provider: 's3' | 'ssm' }`, `gkm compose --stage <local>` (a dry run included) read the S3 store and failed without AWS credentials. The local stage now always uses `.gkm/` state.
